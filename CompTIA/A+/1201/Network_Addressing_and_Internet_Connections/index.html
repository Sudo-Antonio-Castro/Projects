Internet Connection Types

Internet service can reach a site over many different media. Support technicians should know the common options and the tradeoffs each one brings.

Wired ISP Links

  • Cable, DSL, and fiber are common fixed broadband services for homes and offices.
  • Fiber generally offers the best speed and latency, while DSL and cable depend more heavily on local infrastructure and provider design.
  • Business environments may also use dedicated lines or metro-style connections for stronger service guarantees.

Wireless and Remote Options

  • Cellular data can provide primary or backup connectivity through phones, hotspots, or fixed wireless devices.
  • Satellite can reach remote areas but usually has higher latency and stricter service limits.
  • Fixed wireless and point-to-point solutions are useful when wired service is unavailable or expensive to install.

Support Considerations

  • The modem or ISP handoff device usually marks the boundary between customer equipment and provider equipment.
  • Performance problems may be caused by the ISP, local cabling, Wi-Fi conditions, or misconfigured customer hardware.
  • Always identify whether the issue affects only one device, the whole LAN, or the service path to the provider.
Summary

Connection type affects speed, reliability, and troubleshooting flow. The first step is deciding whether the fault is local or with the ISP path.

A+ Exam Tip

On A+, cable, DSL, fiber, cellular, and satellite are all fair game. Be ready to match each one to its most likely use case and limitation.

TCP/IP Concepts

TCP/IP is the addressing and transport foundation of modern networking. The A+ exam expects you to work comfortably with both IPv4 and IPv6 basics.

Addressing Basics

  • IPv4 uses 32-bit addresses written in dotted decimal, while IPv6 uses 128-bit hexadecimal addresses.
  • Subnet masks or prefix lengths define which part of an address identifies the network and which part identifies the host.
  • A host also needs a default gateway to reach remote networks and one or more DNS servers to resolve names.

Address Types

  • Private IPv4 ranges are used inside local networks and require NAT to reach the public internet.
  • Loopback addresses are used for local testing, and APIPA addresses appear when DHCP fails on many Windows systems.
  • IPv6 introduces link-local, global unicast, and multicast address concepts that replace older IPv4 habits.

Configuration Logic

  • DHCP automates address assignment, while static addressing is common for infrastructure devices such as printers, servers, and routers.
  • Misconfigured IP settings can break connectivity even when the cabling and switch ports are fine.
  • Good troubleshooting always checks IP address, mask or prefix, gateway, and DNS together as one set.
Summary

Most connectivity problems become easier once you verify the address, subnet, gateway, and name-resolution path. TCP/IP troubleshooting is about confirming each layer in order.

A+ Exam Tip

A+ questions often hide a DHCP or gateway problem inside a simple connectivity complaint. Check the full IP configuration before replacing hardware.

Network Communications

Network communication relies on protocols that define how systems exchange data. Technicians need to recognize the transport method and the service port in use.

Transport Choices

  • TCP provides reliable, connection-oriented delivery with sequencing and acknowledgments.
  • UDP is faster and connectionless, making it common for real-time traffic where low delay matters more than guaranteed delivery.
  • Knowing whether a service normally uses TCP or UDP helps narrow down filtering and connectivity problems.

Common Ports and Services

  • Know the high-value ports such as 20/21 FTP, 22 SSH, 23 Telnet, 25 SMTP, 53 DNS, 67/68 DHCP, 80 HTTP, 110 POP3, 143 IMAP, 389 LDAP, 443 HTTPS, 445 SMB, and 3389 RDP.
  • Web, email, file sharing, remote access, and name resolution all depend on the right service listening on the right port.
  • If a firewall blocks the needed port, the application may fail even though the device still has basic connectivity.

Protocol Awareness

  • Higher-level protocols ride on top of TCP/IP and provide the services users actually experience.
  • A name-resolution problem can look like an internet outage even when the site is reachable by IP address.
  • Application failures should be tested separately from link and addressing failures.
Summary

Protocol troubleshooting is about matching the service, the transport, and the required port. Once you know that map, firewall and connectivity issues are much easier to isolate.

A+ Exam Tip

Port memorization is still important for A+. When the symptom mentions remote desktop, email, web browsing, or file sharing, think about the default port first.

Network Configuration Concepts

Technicians configure hosts, verify leases, test routes, and confirm name resolution. This lesson ties together the practical tools used in everyday support.

Automatic vs Manual Settings

  • DHCP simplifies client deployment by issuing addresses, masks, gateways, and DNS information automatically.
  • Reservations let a device keep the same address while still being managed by the DHCP server.
  • Static settings are still useful for infrastructure devices and some troubleshooting scenarios.

Translation and Remote Access

  • NAT and PAT let multiple private hosts share public connectivity through a router.
  • VPNs protect traffic over untrusted networks and are common for remote users or site-to-site links.
  • A wrong gateway, missing VPN configuration, or duplicate IP can all break connectivity in ways that appear random to the user.

Everyday Tools

  • Use ipconfig or ifconfig style tools to view addressing, ping to test reachability, tracert or traceroute to inspect the route, and nslookup to test DNS.
  • Netstat and similar tools help confirm active ports and sessions.
  • Start with the simplest local test and move outward rather than jumping straight to the internet.
Summary

Network configuration is where addressing, routing, and name resolution meet. A fast technician knows which setting to verify before making changes.

A+ Exam Tip

For troubleshooting questions, remember the sequence: confirm local adapter settings, test local network reachability, then test remote routing and DNS.
